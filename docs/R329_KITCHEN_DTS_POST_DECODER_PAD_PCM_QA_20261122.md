# R329 — DTS Core PAD/PCM-телеметрия после декодера: VPS 10/10, физический LG 2/2

**Дата:** 2026-11-22. **Область:** только отдельно запущенный лабораторный GStreamer-процесс; **никакой отладки или модификации рабочего Starfish/Lampa**. Итог **ПРОВЕРЕНО для изолированного DTS 2.0/5.1; первопричина холодной тишины Lampa остаётся НЕ ПРОВЕРЕНА**.

## Задача

В R327 подтверждена пользователем **реальная** пара DTS «тишина → AC3 → DTS слышно» в рамках одной загрузки LG; однако штатный `pcm_output.monitor` давал цифровые нули в обоих состояниях. R328 установил, что `audiooutputd` имеет только ALSA `controlC0`, а выход PCM6 открыт PulseAudio, и ни этот счётчик, ни LS2-маршрут `ADEC0→MAIN` не сообщают фактическую амплитуду PCM внутри Starfish.

R329 реализует **экспериментальный инструмент для правильной точки наблюдения**: контролирует DTS непосредственно на `decoder:sink`, а PCM уже после декодирования и конвертации в S16LE — на `pcm_monitor:src`. GStreamer создаётся заново внутри дочернего процесса, завершается `fakesink`; на чужой процесс pad-пробы **не навешиваются**.

## Реализация

- [Исходный C11-инструмент](../tools/r329-isolated-gst-pad-probe.c), SHA256 `4ec7c59cff56df8a22ca6b88cb17d765064ccf500ea845ffe211796a1a5d2070`, финальный исходный коммит `4fa2d1773e3b4077b635be34350400b318baa310`.
- Считает только `STREAM_START/CAPS/SEGMENT` и нарушения их последовательности, формат сегмента (TIME/BYTES), число входных полных BE16 DTS кадров и случаев отсутствующего PTS, количество выходных PCM-буферов и отсчётов, ненулевые отсчёты, агрегаты RMS и peak в dBFS, формат, каналы, частоту. **Не выводит ни одного PCM-отсчёта, raw PCM, PTS, название фильма, URL, arbitrary debug log, private caps-поля или секреты.**
- Допускает только известные имена образцов DTS в каталогах `/tmp/aleks-r329-*`; для native-режима проверяет загрузку `libgstaleksdts16dec.so` **в самом тестовом процессе**, а не в Lampa. Проверяет завершение EOS, 94 BE16 кадра, 94 PCM-буфера, 48 128 отсчётов **на канал**, ненулевую амплитуду и отсутствие ошибок события/отображения. Весь поток — в RAM и `fakesink`; аудиофайлов не создаётся.
- [Воспроизводимая лабораторная регрессия для VPS](../tools/run-r329-isolated-pad-probe-lab.sh), коммит `611b986866e60891efc084345f885c4d3bc3c7d8`. Шифрованные файлы CTS не используются: исходные публичные DTS Core образцы извлекаются из неизменённого R278-архива, SHA256 релиза, двух контейнеров, извлечённых кодированных кадров и C/заголовков проверяются перед запуском. GCC с `-Werror`; SDK-заголовки берутся из SHA256-прикреплённых публичных .deb, распаковываются **только в /tmp**, без установки пакетов и изменения общесистемного реестра GStreamer. `trap` удаляет тестовый каталог.
- [Воспроизводимый ARMv7 EABI soft-float сборщик](../tools/build-r329-armel-pad-probe-lab.sh), коммит `92eda05c6532bb3042c796ba63788fbbee9774d6`. Cross-compiler `arm-linux-gnueabi-gcc`, GStreamer 1.24.2 ARMhf headers, GLib 2.74.6 ARMEL headers, `--no-undefined` и `-rpath-link` на проверенные ARMEL эталонные библиотеки из исторического rootfs LG (`/opt/lg-webos-epk/rootfs87-candidate/usr/lib`). Поскольку это архивный rootfs, сам по себе этот этап **не доказывает** совместимость с кухонным GStreamer 1.24.10, что отдельно проверено реальным запуском.
- [Безопасный стейджер исходных общедоступных DTS образцов](../tools/r329-stage-public-fixtures.py), коммит `694e6a024e9c8363f221a6e112f54b909396e887`, SHA256 `8335f05cf979bf28645888ab252ad6599d1181a97577b79c1be71f0c364e7e7f`. Создаёт в приватном временном каталоге только оригинальные **кодированные** Matroska + raw DTS-файлы после SHA-проверки; не записывает PCM.

## Аппаратный LG kitchen — реальный установленный R278, 2/2 PASS

Авторизованный существующий канал **VPS MCP V3 → AlekS Core → TORMOZ → aleks-kitchen-root**. Компилятор ARM выпустил 32-битный ARMv7 EABI5 soft-float standalone ELF, **23 172 байта**, SHA256 `7f2d160f2465767a0be1249eeedc35b252766898048b33796e3e81ec175a24a3`. **Две независимые полные сборки оказались побайтно одинаковыми**; этот же бинарник был передан по небольшим SHA-контролируемым частям в `/tmp` LG и реально выполнен.

На LG GStreamer 1.24.10 использовались `decodebin` и **фактические оригинальные библиотеки R278**, при временно ограниченном GStreamer registry и `GST_PLUGIN_FEATURE_RANK=aleksdts16dec:350,decproxy:0` **только для тестового дочернего процесса**. Сохранён только суммарный результат в задаче AlekS Core `3a5c1574832e82e4610d4c09c637cd5f`: `COMPLETED exit0`, оба `RESULT=R329_PAD_PROBE_PASS`.

|---|---:|---:|
| Исходный `decoder:sink` | **94 полных DTS** | **94 полных DTS** |
| Входные события `CAPS` | **2 × `audio/x-unknown`** | **2 × `audio/x-unknown`** |

| Полный PCM RMS | **−24,13 dBFS** | **−29,75 dBFS** |

**Отдельно о `audio/x-unknown`.** Первая аппаратная версия теста корректно измеряла PCM, но пометила запуск `FAIL`, потому что требовала буквально `audio/x-dts` на входе `decodebin`. Новый ограниченный классификатор принимает `audio/x-unknown` **только в специально включённом режиме native R278 при строгой проверке всех 94 BE16 DTS кадров, правильных событий, фактического оригинального R278 и валидного ненулевого PCM**. Это наблюдаемое свойство LG-ветки, **не подтверждение дефекта или способа исправить Lampa**.

- Проверенный бинарник + метаданные сохранены **приватно на VPS**: `/opt/gamefree24-vps-mcp/private/dts-r329-20261122/`, права каталога `0700`, файлы `0600`. Бинарный SHA256 `7f2d160f2465767a0be1249eeedc35b252766898048b33796e3e81ec175a24a3`, манифест SHA256 `767718f41ec5fa62900e4a0410a072dff0c169ebf5fe833c707f08427ee1656c`.
- Задача очистки LG `1116e6a3df15074606ec33f941a6fa55`, `COMPLETED exit0`: оба изолированных каталога `/tmp/aleks-r329-probe-20261122` и `/tmp/aleks-r329-qa-20261122` удалены. **`umediaserver` и `audiooutputd` остаются active**, все 4 официальных плагина R278 соответствуют релизным SHA256, `installed.env` равен действующему `umediaserver.env`.
- Нет записи PCM, хранения названий фильмов или URL, чтения реального пользовательского фильма, замены библиотек, службы `umediaserver`, патча прошивки, загрузки корневого кода в работающий Starfish, прерывания текущего просмотра, установки R325 в рабочий плеер.

## Что остаётся для пользовательского исправления

**Не путать изолированное измерение с определением первопричины реального холодного запуска.** Инструмент теперь проверен на **правильном выходе после R278-декодера**, но пока **только в независимом GStreamer-процессе**, с публичными CTS образцами. При подтверждённой владельцем паре R327 не было возможности смотреть именно эти pad-пробы внутри Starfish.

Следующий этап — отдельное, строго ограниченное и обратимое **наблюдение настоящего Starfish** при первом DTS после перезагрузки. Нужны скалярные метрики `STREAM_START/CAPS/SEGMENT`, PTS, количества входных DTS и выходных PCM, RMS/peak. Разрабатывать и проверять такой probe сначала на изолированных процессах; **загрузку в рабочий Starfish, изменение `umediaserver.env`/декодера или перезапуск медиаслужб выполнять только после отдельного разрешения и проверенного отката**. До этого не утверждать, что ошибка связана с `audio/x-unknown`, отсутствующим PTS или BYTE-сегментом.
