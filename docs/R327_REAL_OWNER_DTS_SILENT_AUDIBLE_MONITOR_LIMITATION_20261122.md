# R327 — реальная пара DTS «тишина → звук» на кухонном LG: выходной PCM-монитор не различает состояния

**Дата:** 22 ноября 2026 года. **Проверено на физическом телевизоре**, по существующему каналу GameFree24 VPS MCP V3 → AlekS Core → TORMOZ → `aleks-kitchen-root`. **Первопричина холодной тишины DTS остаётся НЕ УСТАНОВЛЕНА.**

## Реальная последовательность

1. Владелец сообщил **«DTS — тишина»**, не переключая дорожку. Выполнили ровно один проверенный комплект R326 `before → pcm_output.monitor → after`, задача `e9d51678548bc081b536c1dffa10dc8e`, COMPLETED exit0.
2. Снимок **silent**: 2026-11-22T13:25:11Z, одна загрузка LG с идентификатором в виде безопасного отпечатка `6285fe0b79d47c3c`. Monitor **70 772 PCM-отсчёта, 0 ненулевых**. Хранится только разрешённый JSON, без аудио, приватный VPS `/opt/gamefree24-vps-mcp/private/dts-r326-20261122/real-owner-silent-132511Z.json`, SHA256 `3804c62975f5249fe58ab57654cc2f752db9e3f643ff08af10e8ccf5cec8c130`.
3. Владелец вручную переключил **DTS → AC3 → DTS**, после чего подтвердил **«DTS — звук есть»**.
4. Снимок **audible**: 2026-11-22T13:26:58Z, задача `67bf200c5d7a2ed7a46cf3659ee7c298`, COMPLETED exit0. **67 810 PCM-отсчётов, 0 ненулевых** на том же `pcm_output.monitor`. Приватный VPS `/opt/gamefree24-vps-mcp/private/dts-r326-20261122/real-owner-audible-132658Z.json`, SHA256 `02e5c7811bd7e172d07aadcace2fe4793614adc91002099eee692997a0ca12f9`.
5. Отпечаток загрузки **совпадает**; разница между началами снимков **107 секунд**. Исходные SHA256 инструментов R326 проверены на телевизоре до обоих снимков.
6. Обе точки наблюдения относятся к **подтверждённым владельцем** состояниям и уже не являются `unclassified`. Пользователь не должен снова воспроизводить этот дефект только ради этих счётчиков.

**Ключевая коррекция интерпретации R326:** монитор `pcm_output.monitor` отдаёт **цифровой ноль даже при реально слышимом DTS**. Поэтому **его показания НЕ МОГУТ различить неисправное и рабочее DTS воспроизведение именно на проверенном пользовательском маршруте**. Ноль в момент тишины **не доказывает**, что декодер выдавал нулевой PCM, и **не локализует** потерю звука «до PulseAudio».

Возможные объяснения: реальная дорожка DTS выводится через иной, низкоуровневый LG `ADEC0→MAIN` маршрут, обходящий наблюдаемый monitor sink; monitor источник не отражает поток из-за особенностей драйвера/политики; либо monitor захватывает не тот sink. **Конкретное объяснение не подтверждено:** для этого требуется проверка правильного native audio handoff и/или скалярный probe непосредственно до PulseAudio/на DSP-выходе. Из одних метрик невозможно сделать вывод, что R325 уже исправил холодную тишину.

Важно: [R318](R318_REAL_KITCHEN_FIRST_SILENT_TO_AUDIBLE_PAIR_20261122.md) ранее наблюдал в реальной паре **`ADEC0→MAIN`, `tv_external_speaker`, `mute=false` в обоих состояниях**. Это также не различило тишину и звук.

## Инженерный следующий шаг

- **Не повторять PulseAudio output monitor как датчик DTS амплитуды**. Для R328 требуется дифференциальная read-only проверка реального `audiooutput / ADEC0→MAIN` и нативного медиапути, затем минимальный, обратимый скалярный инструмент в *правильной* точке до DSP/входе аудиорендера.
- Проверить независимо, **получает ли `dcadec_context_filter` ненулевой результат в первом проблемном запуске**, и какие `STREAM_START / CAPS / SEGMENT` получает Starfish в этот момент. Не выводить из текущих результатов, что причиной является `BYTES→TIME` или пакетизация.
- **Для live pad/decoder instrumentation, замены plugin или временного изменения службы требуется отдельное разрешение владельца, backup и проверка отката.** В R327 никакой установки или изменения R278, `umediaserver`, ALSA маршрутов, системных частей или прошивки не выполнялось.

**Окончательный статус:** реальная пара «DTS тишина → DTS слышно» получена и сохранена; структурные параметры PulseAudio/ALSA не различают состояния; монитору `pcm_output.monitor` на этом маршруте DTS доверять нельзя; **причина холодного отсутствия звука и постоянное исправление остаются НЕ ПРОВЕРЕНЫ**.
