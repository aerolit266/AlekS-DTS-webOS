# R341 — изолированный GStreamer adapter для acquired-resource

Статус: **LAB ONLY / НЕ УСТАНОВЛЕНО / не исправление DTS на LG**.

## Исходная проблема

На кухонном LG webOS 26 при холодном воспроизведении DTS была тишина; после ручного AC3 → DTS звук появлялся без перезапуска Starfish/uMS. В событиях R339 первоначальный DTS CAPS возникал примерно за 569–574 мс до приобретения аудиоресурса. Однако **холодный запуск тоже содержал acquired-resource и создание OMX-декодера**. Отсюда нельзя делать вывод, что простое повторение события исправит звук.

R340 проверила модель жизненного цикла гранта и GStreamer pad API по отдельности. R341 объединяет их в неинтегрированный адаптер с настоящими GstEvent/GstPad.

## Реализовано

- **r341-gst-grant-bridge.h**: интерфейс мостика на один медиа-конвейер.
- **r341-gst-grant-bridge.c**: сохранение оригинального события через gst_event_ref, валидация GST_EVENT_CUSTOM_DOWNSTREAM/acquired-resource/audio-port [0..15]; явный replay через gst_pad_push_event только после готовности нового аппаратного child; учёт ACK; очистка на RELEASE/UNLOAD/policy suspend; максимум две ручные попытки на поколение; защита от реентрантной инвалидизации.
- **r341-gst-grant-bridge-qa.c**: 20 сценариев с реальными GStreamer pad/event API, но только искусственными pads.
- **r341-qa.sh**: нативная + ASan/UBSan сборка на машине с установленными пакетами разработки GStreamer; **сам ничего не скачивает и не устанавливает**.

Контракт интегратора:

1. Единственный экземпляр R341Bridge принадлежит одному uMS/Starfish pipeline. Метки epoch/generation используются только внутри этого экземпляра; не хранить ID, URL, путь или пользовательские аудиоданные.
2. Только доверенный источник реального acquired-resource может вызывать r341_observe_real_grant. Совпадение имени и порта **само по себе не доказывает подлинность**: интегратор должен проверить точку захвата.
3. Методы вызываются последовательно на одном GStreamer control thread; параллельный вызов без блокировки не поддерживается.
4. Исходное событие продолжает идти по штатному пути. Интегратор должен вызвать r341_original_ack с сохранёнными epoch/generation/serial **после** настоящего результата доставки, иначе возможен дубль.
5. Вызывать r341_child_gone при удалении старого decproxy child, затем r341_child_new(TRUE) только для аппаратного декодера; r341_replay — только после связывания pads. Программным AlekS DTS-декодерам грант не передавать.
6. При RELEASE, UNLOAD, потере аппаратных прав немедленно инвалидировать сохранённую ссылку. После policy resume ждать **новый настоящий грант**.
7. Результат gst_pad_push_event()==TRUE означает лишь согласие downstream pad принять событие, **не появление звука**. Конечный критерий — реальные PCM/rtkalsasink измерения + слышимый DTS после холодного включения.

## Выполненный QA

На финском VPS с GStreamer runtime 1.24.2 и заголовками, извлечёнными из официальных Ubuntu .deb только в лабораторную директорию (никаких системных установок):

- Нативный gcc -std=c11 -O2 -Wall -Wextra -Werror -pedantic: **20/20 PASS**.
- gcc -fsanitize=address,undefined, с LeakSanitizer: **20/20 PASS**, ошибок памяти и UB в выполненных сценариях не обнаружено.
- Искусственные аппаратные и software child, ранний/поздний грант, смена child, FLUSH, отказы, ограничение повторов, реальные ACK, устаревший ACK, RELEASE, suspend/resume, изоляция pipeline, reentrant release, смена epoch.

ARM GStreamer QEMU runtime **не проверен**. Проведение тестов на настоящем webOS decproxy **не выполнено**.

## Условия выпуска аппаратного исправления (пока не выполнены)

- Получить исходники конкретной webOS 26 decproxy интеграции либо безопасный открытый extension hook; исходников внешнего aleksdts16dec в публичном архиве R278 нет.
- Доказать на реальном объекте, что grant пришёл до готовности конкретного аппаратного child или потерялся после замены, и что повторное событие действительно ему требуется. В R339 были grants и при холодной тишине, поэтому причинность не доказана.
- Зафиксировать положительный контроль real DTS→PCM→rtkalsasink без записи звукового содержимого, и убедиться, что AC3, normal PCM, переключение потоков, seek, resume, 4K-видео не регрессировали.
- При аппаратной пробе использовать отдельный opt-in процесс и план отката, не заменять системные библиотеки, UMS, OMX, boot/rootfs. Никакого автоматического запуска на LG.
- Статус внедрения сохранять **NO-GO** до полного физического E2E.

Выпуск R278 оставлен без изменений.
