# R337 — Realtek audio sink: ARM32-инструмент и аппаратный QA на кухонном LG

**Дата:** 22 ноября 2026. **Результат:** новый пассивный наблюдатель собран и проверен на физическом LG, **2/2 PASS**, рабочий DTS R278 **не изменялся**. Корень холодной тишины в Lampa пока **не установлен**.

## Почему теперь измеряем Realtek sink

Из подтверждённой владельцем реальной пары R334/R335 известно, что при первом DTS после перезагрузки звук отсутствует, хотя `audio/x-dts` распознан, `audio-port=0` выделялся, декодер/decproxy создавался и выдавались `STREAM_START/CAPS`. После ручного DTS→AC3→DTS звук появился без смены PID Starfish, службы и PulseAudio. Вторая передача аппаратного ресурса и переключение декодера зафиксированы в **16:23:23 UTC**, но причинная роль этой операции ещё не доказана.

**Новое физическое наблюдение R337:** в Starfish с установленной R278 загружены собственные плагины LG/Realtek `libgstrtkalsa.so`, `libgstaudioconvert.so`, `libgstaudioresample.so` и OMX. Запрос `gst-inspect-1.0` на самом LG подтвердил:

| Фабрика GStreamer | Rank | Принимает |
| --- | ---: | --- |
| `rtkalsasink` — Realtek ALSA sink bin | 257 | PCM `S16LE` 48 кГц, 2/6/8 каналов; AC3, E-AC3, DTS |
| `rasink` — Realtek SoC audio hardware sink | 0 | Те же raw/compressed caps |

Существование этих фабрик и отображение их библиотеки в `/proc/<pid>/maps` **не подтверждают**, какой конкретно sink pad используется в текущей Lampa. Однако они дают конкретную границу для измерения: **после DTS-декодера, перед входом Realtek sink**. `pcm_output.monitor` из R327 не подходит: он возвращал нули как в слышимом, так и в бесшумном состоянии.

Ядро кухонного LG показывает `aarch64`, но реальный процесс Starfish, `libgstrtkalsa.so` и установленные `libgstaleksdts16dec.so` — **ELF32 ARM EABI**, что проверено по сигнатурам ELF первых 20 байт. Поэтому используется ARMv7 EABI soft-float, а не AArch64 ABI.

## R337 observer

[Исходник R337](../tools/r337-bounded-realtek-sink-observer.c) — отдельное развитие ранее проверенного R331, без изменения R331 или оригинальной R278.

- Наблюдает `gst_pad_push` / `gst_pad_push_event` и всегда передаёт управление штатной функции, не изменяя события, `GstBuffer`, CAPS, станцию, маршрут, громкость, decoder или hardware.
- Считает compressed DTS BE16 на входе декодера, PCM после декодера/конвертера и отдельно входы **`rtkalsasink` / `rasink`**, различая raw PCM S16LE, compressed DTS/AC3 и неизвестные caps. У реального bin и вложенного sink счётчики **раздельные**, так как один буфер может пересечь оба.
- Для raw PCM вычисляет только ненулевые отсчёты, RMS и peak максимум по первым **1024 отсчётам каждого буфера**. Сам звук или видео, URL, фильм, имена пользовательских потоков и байты PCM/DTS не сохраняются. Данные между фабриками одного процесса могут относиться к разным потокам — **это не доказательство идентичности конкретного DTS-трека**.
- `LD_PRELOAD` разрешён только при явном `ALEKS_R337_ENABLE=YES` и в Starfish-процессе. Отдельный `ALEKS_R337_ISOLATED_QA=YES` разрешает `fakesink` **только для лаборатории**. Каталог метрик должен иметь mode `0700` и известный префикс; файлы `0600`; автоматический предел наблюдения **180 секунд**.
- ELF не содержит прямой линковки на GStreamer/GLib; в ARM ELF `DT_NEEDED` только `libm.so.6`, `libc.so.6`, `ld-linux.so.3`. Это снижает риск загрузки сторонних библиотек в `umediaserver`.
- Source commit `e411a8aba934aaba7f090470f6231905266056ab`; SHA256 `528bcf0a2029312a958eaf1a424eefb9f2ae728c4e03f03206745ba7bcc659da`.
- ARM32 бинарник: **27 768 байт**, SHA256 `2e460188129b3cf946a10b66f21c2dcc6adb1994d35ab8faf9b3d0576d94f595`. Бинарник хранится только в приватном хранилище VPS, не является релизом/установщиком.

## Репродуцируемые проверки

На VPS GStreamer 1.24.2 скачаны и распакованы **только во временный каталог** заголовки SDK, без `apt install` и без системных обновлений. Сборка `gcc -std=c11 -O2 -Wall -Wextra -Werror -fPIC -shared` прошла, `--no-undefined` включён. Результат на исходных R278 DTS Stereo/5.1 с `fakesink` — оба `94/94` PCM-буфера, 48 кГц, ненулевой сигнал.

Защитные тесты VPS: отсутствие QA-разрешения в обычном процессе → нет JSON; отсутствие `ALEKS_R337_ENABLE` → нет JSON; укороченный вариант `R337_WINDOW_SECS=4` наблюдал только **50 из 94** буферов при искусственно замедленной 7-секундной обработке. Общее elapsed дочернего процесса равно примерно 7 секундам; **оно не равно активному окну наблюдателя**.

Для физического LG собрана ARMv7 EABI soft-float версия через `arm-linux-gnueabi-gcc -march=armv7-a -mfloat-abi=soft -Werror` с заранее SHA256-проверенными заголовками SDK. Бинарник передан по уже существующему прямому SSH TORMOZ → LG, без новых туннелей, смены ключей или проксирования файла через VPS; SHA256 на LG совпал.

[Исходный скрипт native QA](../tools/r337-verify-realtek-sink-observer-lg.sh) (commit `a590873c9f4cfe4aa32edd43af3f1eeffbd6fb5e`, SHA256 `1ebc9b2d62050bbf963bb8c2c1d34226eeec75298432a16db15ded7a92fee6df`) использует **встроенные в R278 публичные DTS-образцы**, краткоживущий `gst-launch-1.0` и только `fakesink`, не `rtkalsasink`; собственный GStreamer registry только в `/tmp`.

| --- | ---: | ---: |
| Входные DTS Core BE16 | 94 | 94 |
| Выход PCM S16LE в тестовый `fakesink` | 94 буфера | 94 буфера |
| Проверенная выборка PCM | 96 256 отсчётов | 96 256 отсчётов |

Данные — **выборка на границе QA fakesink**, не полный многоканальный PCM и не звук из динамиков. Никаких пользовательских аудиодорожек, исходного фильма и аудиозаписей не использовалось.

Два исходных скалярных JSON сохранены приватно с SHA256:

- surround: `aebce7ee7e9974a79b7a1f509475a69582d697ec48b5e13c7d42877f076c0d65`.
- приватный манифест `R337-VERIFIED-QA-MANIFEST.json` SHA256 `29117215b5c76d1b8bd6a5c65dea89f873fcea47da45a3d92331e5aba2c31793`, файлы и бинарник `0600`, каталог `0700`.

**Откат и очистка:** временный каталог LG удалён только после проверки отсутствия его библиотеки в картах всех работающих процессов. На телевизоре результат `R337_NO_ACTIVE_HOOK_MAPPINGS=PASS`, `R337_TV_TEMP_CLEAN=PASS`; `umediaserver` и `audiooutputd` остались `active`. Два временных файла TORMOZ также удалены с проверкой. Установленные R278/системные службы/прошивка не менялись.

## Следующий этап — только после нового разрешения на сервисный тест

Для измерения **на реальном входе Realtek sink при холодной DTS-тишине** понадобится заранее включить ограниченную инструментовку именно при старте нового Starfish. Проверенная схема R331 (временный systemd override в RAM + watchdog перед перезапуском медиаслужбы) может быть адаптирована под R337, но на следующем холодном включении потребуется отдельное явное разрешение владельца и согласованное окно запуска Lampa.

До этого никаких перезагрузок, постоянных `LD_PRELOAD`, изменений `umediaserver.env`, ручных переключений звука или установки R337 в рабочий процесс. **Нельзя объявить DTS исправленным**, пока первая тишина и восстановление не сопоставлены по фактическому PCM/DTS на входе реального Realtek sink.
